# BBS 3.3.2.0：本机 LTK 原始组件兼容修复

## 当前结论（不要混淆两层问题）

1. 用户原始错误是游戏附加阶段的 SetWindowsHookEx failed: 0x00000000；日志仅能证明钩子安装失败，不能据错误0认定是Vanguard、权限、杀毒或签名必然阻止。当前BBS、Rose和客户端均实测管理员权限，不再重复建议“勾管理员”。
2. 为作同版本对照，本机单独导入了官方1.30.4原始host/DLL，均通过精确SHA-256与Windows Authenticode Valid检查。随后旧3.3.1按内置派生文件的大小检查，触发Component file size mismatch；这次修复流程造成了新的启动阻塞。
3. 3.3.2修复第二层阻塞：严格识别两个已知完整组合——原内置派生组合、同版本官方原始组合。**原始游戏注入问题还没有得到成功训练模式日志证明，不能宣布换肤已修好。**

## 实施内容

- 仅在Rose1.4.9的两个固定工具路径及LTK1.30.4的两个固定文件上启用白名单。
- 官方host：1239304字节，SHA-256 27DE1BFDBF37129E42C12B18CC7B4F75C15D39BCD7AFEFE65C4C33D0E99FE856。
- 官方DLL：834816字节，SHA-256 0B024A3A839F55FF7CF7EE93D9ED2078BCBB07D3B7F320463D678F8A6209E5FF。
- 不接受“大小相同”或“任意签名有效”的其他文件；四个文件逐个哈希，禁止同目录混搭和Rose/LTK两份副本不一致。
- 就绪缓存与启动前均复核；没有关闭组件完整性检查，也没有改变备份/缓存同步规则。
- 新建Rose目录时，先按原清单验证原始CAB，再从本机已经导入并核验的LTK目录绑定对应原始文件；只替换新建、尚未发布暂存目录内已知的派生文件，不覆盖既有用户目录。
- Akari“没有可关闭窗口、进程仍在运行”改为托盘退出提示，不再作为红色通用错误显示，也不会自动强停。

代码：[工具管理器](<../src/core/tool_manager.cpp>)、[工具中心提示](<../src/app/main.cpp>)。

## 许可与分发范围

本机导入属于用户私用，不把官方签名host/DLL作为重新打包的发行文件加入BBS或CAB。现有三份CAB和组件清单保持字节不变，因此既有标记与配置无需迁移。**这不是全新机器已经自动安装官方原始补丁的承诺**；全新机器仍使用原内置派生组合，其真实游戏兼容性未被本次证明。

Rose官方[1.4.9说明](<https://github.com/Alban1911/Rose/blob/1.4.9/README.md#ltk-patcher-requirement>)说明了用户从LTK Manager安装目录取得两个文件并复制的方式。LTK[补丁许可](<https://github.com/LeagueToolkit/ltk-manager/blob/v1.30.4/LTK-PATCHER-LICENSE.md>)对签名重新分发与完整未修改官方发行物作了区分；不能因此声称获得上游背书。
