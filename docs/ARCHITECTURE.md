# Native 3.3 DIRECT 架构（候选 3.3.0.0）

## 线程与调度

- UI 线程负责原生五页窗口、主题、托盘和最终结果展示；UI 后台队列串行处理启动、配置恢复和退出，不用默认配置覆盖不可读/损坏文件。
- [Service](<../src/core/service.cpp>) 工作线程串行执行设置和文件任务，排队 ACK 不等于完成。取消通过原子标记/纪元旁路送达，文件/复制进度回调只读原子状态，不逐文件或逐块执行全系统进程探测。
- [工具管理](<../src/core/tool_manager.cpp>) 使用独立 worker，负责版本化组件释放/完整性检查、工具进程和跟随大厅；不占 DIRECT 文件队列，普通 BBS 启动不必先解包工具。跟随默认关闭，在线启动、离线请求正常关闭、未知忽略；显式启动不受在线条件限制。准备已有无效目录只报错，不自动修复。
- 独立大厅监控默认每 500ms 采样，首次观测在线立即安排恢复，不等第二次样本；文件 IO 不阻塞监控。自动工作以大厅在线为调度条件，不以对局状态作为写入许可。
- 开关关闭或大厅离线/未知时停止安排自动工作并请求取消；没有对局结束追加备份、下线最终备份或自动 Game 清理。

## DIRECT 数据流

业务白名单只有 saves/、shards/ 子树和根文件 bot_5.dll、config.ini、hc.dat、HID.dll、shards.json、user.ini；不是整套游戏安装目录。

1. **恢复：物理缓存 → Game。** [引擎](<../src/core/sync_engine.cpp>) 只枚举缓存白名单一次，逐文件调用 CopyFileExW 直接覆盖，即使内容相同也复制。不扫描完整 Game 作比较，不做全树哈希、同内容跳过、暂存原子提交或最终整树复验；不删除 Game 额外项。
2. **在线定时全量镜像：物理 Game → 缓存。** 默认 5 分钟，可设 1–1440 分钟。Game 当前白名单为真值，覆盖同名项，删除缓存中源端不存在的全部受管差集。**仅大厅确认在线时，完整空 Game 才清空所有受管缓存项**；白名单外内容保留。枚举错误不可伪装为空。
3. **手动备份 / 导入。** 手动备份为复制型，不额外删除缓存差集；导入只复制显式源的白名单，不移动或删除源。
4. **任务结果。** 空缓存无文件可恢复，不伪造复制成功；失败恢复不留下持久冻结，不阻止下一次在线定时镜像。后续周期可能把当前 Game 写回缓存，包括先前部分还原的状态。

自动 fullMirror 的 `mirror/verified` 删除前边界额外执行一次新鲜 `ProbeLobby`，确认仍在线才开始删除；此标签不代表内容复验。离线/未知即使 Game 随后为空也无自动复制、删除或最终补派任务；恢复/逐文件/逐块仍无进程探测。复制取消回调使用 `PROGRESS_STOP` 留下当前部分目标，而不是 `PROGRESS_CANCEL` 删除目标；错误后的状态按 Windows 实际结果报告，覆盖/截断及已完成变更无回滚。

## 移除的业务保护

不再使用持久还原保护、目录所有权认领/独占授权、物理身份批准、对局等待、哈希跳过、暂存原子复制、最终内容复验、删除墓碑或历史回补。旧管理文件、墓碑及旧历史目录原样保留并忽略，不读取为业务真值、不自动清理。不得从旧元数据重新解释当前物理缓存。

## 保留的范围与系统边界

- 配置路径规范化、Game / 缓存不相同或互为祖先、基本重解析点与白名单范围检查仍保留；它们限制应用操作范围，不是目录身份批准，不承诺抵御所有路径竞争。
- 同步业务不修改 ACL、不提权绕过拒绝、不关闭系统安全软件；显式启动 Rose 管理员进程可弹 UAC，不表示 BBS 主进程统一提权。实际权限、占用、共享冲突、磁盘及路径错误由 Win32 返回并明确报告。
- 直接 CopyFileExW 覆盖没有业务暂存/原子替换；取消/错误可能留下部分或截断的目标。已复制/删除项不回滚，不保证源目录静止、全树快照或最终字节复验。
- 成功、跳过、部分失败、取消和失败必须区分；不可把排队、可读、零错误文本或局部完成当作整个任务成功。不提供历史恢复点、快照、滚动代、自愈或坏代回退。

## 配置、日志与发行

[配置模块](<../src/core/config.cpp>) 保留严格解析、缺字段迁移、未知字段、协作锁、配置 CAS / 字段合并与配置原子保存；它们只保护配置事务，不表示业务文件原子复制。自启动仍只通过当前用户 Run 键设置，失败需反馈；测试可抑制真实注册表副作用。

[日志模块](<../src/core/logger.cpp>) 记录阶段、操作耗时与真实错误，UI 展示有界日志；正常退出先请求取消再等待后台返回，不强杀 IO，不保证内核/驱动阻塞时固定时间退出。

主程序仍为面向 Windows 10 build 10240+ 的 x86 原生 UI/备份程序；集成发行是一个 EXE，约 140 MB 量级，最终大小以发行文件为准。首次准备工具会释放完整运行目录到 `%LOCALAPPDATA%/LOLBackupV3/components/<id>/<version>`，不再承诺无外部运行文件。第三方工具为 x64，其 Windows/系统先决条件不等同于 BBS 最低条件：Rose/Pengu 涉及 .NET Framework 4.7.2，Akari x64 更新器需要未随原包提供的 VCRUNTIME140.dll；Electron/Node 运行文件则已随 Akari 携带。原有测试及新增工具管理目标的通过数均以本次实际运行报告为准，不沿用旧计数。候选版本性能收益与通过统计必须以实际构建/回归/同机同数据测量为准，此文不预先宣称提速比例。

## 工具组件与进程边界

- Rose 1.4.9 完整运行层内直接放入 LTK 1.30.4：`_internal/injection/tools/{host,dll,license}`；host/DLL 配对按二进制许可移除上游签名并保留许可，不加入完整 GPL LTK Manager UI。现有桌面 Rose-CN 与 `E:/Rose` 不改动。
- Akari 1.5.1 是独立 Electron 应用；启动不等于其客户端连接/所有功能成功，不能把内部 Electron IPC 冒充稳定 BBS API。官方不支持腾讯服务器。
- 关闭只请求受管工具正常退出，工具可能藏至托盘；强制停止需确认且只针对受管工具，不结束游戏或 Riot 客户端。
- Rose 静态游戏构建兼容阈值 `2026-10-28T23:06:41Z` 不是墙钟到期，未来游戏构建需官方 patcher 更新。未做真实游戏注入测试，不承诺账号/条款安全。
- 组件来源/摘要/许可与原生程序独立记录；保留 Electron/Chromium/Node 等通知，不以 Akari MIT 覆盖所有依赖义务。工具隔离检查 `--verify-tools <绝对隔离根>` 为 dry-run，不启动真实工具、游戏或同步服务。
- 详细操作与运行要求见 [工具中心使用说明](<工具中心使用说明.md>)。
