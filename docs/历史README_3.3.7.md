本次在概览右上增加非卡片式Rose/Akari快捷启动，适配主题/DPI，并减少无效绘制、日志滚动整窗刷新及绘制/布局中的目录查询；原同步业务与所有工具载荷保持不变。完整官方Rose 1.4.9与League Akari 1.5.1仍集成在一个EXE中，只有两个打开入口，点击自动准备。没有独立LTK Manager或安装器。3.3.4在20:06真实训练确认hook失败，不能视为修复；3.3.5仅固定一个有依据的新对照：原始官方签名的1.29.0配对（host与1.29.1相同），放到新Rose版本目录，旧目录和配置保留。位数、来源、构建范围、选肤/构建和权限等检查记录见[全面检查记录](<docs/全面检查与签名对照_3.3.5.md>)。尚未验证游戏效果，不承诺换肤成功；本机私用，不是已获准公开再分发的签名工具包。

基于原 LOLBackupV2 源码包的原生桌面重构版，面向标准 Windows 10 桌面版 1507（build 10240）及以上。主发行是一个 **x86 PE**，可在32位系统原生运行、64位系统经系统WOW64运行；ARM仿真/Win10 S/企业策略或裁剪系统不作统一保证。

## 运行

直接双击桌面上的单个 [BBS自动工具.exe](<../BBS自动工具.exe>)，不用先解压另一个安装包。**单 EXE 分发不等于运行时没有文件**：3.3.0 内嵌 Rose 1.4.9（含 LTK 1.30.4）与 Akari 1.5.1 完整组件，约 140 MB 量级，准确大小以最终发行文件为准；首次准备工具时释放到 `%LOCALAPPDATA%/LOLBackupV3/components/<id>/<version>`。BBS 自身的 C++ 支持静态链接，不依赖 WebView2、浏览器、Python、Node.js 或 .NET 显示界面/执行备份；工具的 Python/Qt、Electron 等运行文件随包释放，Rose/Pengu 的 .NET Framework 4.7.2 与 Akari 更新器的 VC++ x64 先决条件仍需区分。Win32/COM/Common Controls/GDI+/系统 UCRT 由 Windows 提供。不能在缺失系统组件、Wine/Nano Server 或任意旧版 Windows 上保证运行。

EXE 无需附带预置配置文件即可启动。删除旧运行配置后，首次启动使用默认值；在保存设置时自动生成用户配置，原路径和自定义间隔需重新选择。源码包只保留源码、资源、文档及构建/测试脚本，不内置重复 EXE 或旧编译工具链。

- BBS 普通启动不提权、不要求先准备工具；“跟随大厅”默认关闭。显式启动 Rose 管理员进程可能出现 UAC；第三方工具可联网、创建子进程、加载其自身 DLL，不能再对整个集成包宣称“无运行时/无子进程”。
- BBS 业务源码仍使用内置 nlohmann/json 3.11.3（MIT）；现额外分发完整第三方工具及依赖。保留 [第三方声明](<THIRD_PARTY_NOTICES.md>) 与组件实际许可证；Akari MIT 不覆盖其他依赖，LTK 二进制自定义许可与 Manager GPL 源码范围不同。
- 全新界面由原生 C++ 绘制，深浅主题、5页导航、DPI适配、键盘操作、原生路径选择和托盘菜单。
- 下载的Noto中文字体和Font Awesome图标字体都在EXE中，内存解码/私有注册，不安装字体；NASA真实摄影、Noto现成PNG图标也内嵌。没有生成图片素材，完整署名与许可在应用“关于与开源许可”内可读/复制。
- 用户自行提供的BOT业务文件是备份数据，不是本工具运行库；本工具不加载、执行或提供它们。

## 第一次使用

升级前先退出旧版程序，并在Windows任务计划程序中停用你确认属于旧版的备份/监控任务，避免两套程序同时写游戏。新版不会自动删除旧任务、旧安装目录或旧数据。

1. 选择外服 League of Legends 的 **Game** 目录。识别仅基于文件布局/可读PE与未认证版本资源启发式，不是 Riot 数字签名或来源认证。
2. 若已有旧版桌面缓存，进入“备份任务 → 导入已有缓存”，显式选择旧缓存目录。导入只复制识别的业务项，不删除或移动源。不要直接把游戏目录、磁盘根或资料目录设成镜像目标。
3. 缓存默认存于当前用户 LocalAppData 下的 LOLBackupV3 缓存子目录。选择哪个普通目录就使用哪个目录，不认领所有权、不创建身份批准记录；切换位置不会自动迁移旧数据。
4. “立即备份”从游戏目录复制到缓存；“恢复到游戏”将物理缓存中的白名单文件直接覆盖到 Game。不会等待对局退出，也不会因游戏进程未知而拒绝手动恢复。直接复制失败或取消可能留下部分或截断的目标文件，没有回滚。
5. 自动备份开关关闭时，不再执行自动备份/自动恢复。大厅检测绑定当前Windows会话和配置安装路径，采样错误标为未知而不是伪离线。

业务范围：saves/、shards/ 及 bot_5.dll、config.ini、hc.dat、HID.dll、shards.json、user.ini。不是整个游戏安装目录的备份。

## DIRECT 模式：大厅联动与物理目录真值

本候选版本按明确选择移除业务层保护，优先减少重复工作；这不是已测得的速度承诺，实际耗时与改善幅度以同机同数据基准结果为准。

1. **大厅启动 / 首次观测在线**：独立监控线程默认每 500ms 采样；首次观察在线即安排缓存 → Game，不等第二次确认，不等对局退出。恢复只枚举物理缓存白名单一次，对每个文件使用 `CopyFileExW` 直接覆盖；即使内容相同也复制，不预扫 Game，不做哈希跳过、暂存原子替换或最终整树复验。
2. **大厅持续在线**：按自定义间隔（默认 5 分钟，可设 1–1440 分钟），以物理 Game 当前白名单为真值全量镜像到缓存：覆盖同名文件，删除缓存中源端已不存在的受管项。**只有大厅确认在线时，完整枚举得到的空 Game 才会清空全部受管缓存项**；白名单外内容不动。
3. **大厅离线 / 状态未知**：停止安排自动工作并请求取消；不执行下线最终备份、对局结束备份或自动清理 Game。
4. **再次观察在线**：再次从当时实际存在的缓存直接恢复，再按间隔镜像。空缓存无文件可恢复，不伪造复制成功；失败恢复只报告本次错误，**不会冻结以后的定时镜像**，也不要求人工批准目录或手动备份解除冻结。

自动全量镜像在 `mirror/verified` 删除前边界仅额外执行一次新鲜 `ProbeLobby`，确认仍在线才开始删除（该阶段名不表示内容复验）。离线或未知时，即使 Game 随后变空也不自动复制、不删除、不补派最终任务。恢复及逐文件/逐块回调仍不做进程探测。

复制取消使用 `PROGRESS_STOP`：停止并留下当前部分目标，而不是用 `PROGRESS_CANCEL` 在取消清理中删除目标；失败/取消无回滚，旧目标可能已被覆盖或截断，错误后的目标状态按实际 Windows 结果报告。

工作线程的逐文件/复制进度取消判断只读取原子取消/停止及调度状态，不逐文件或逐块重新枚举全系统进程；大厅监控独立于文件任务。手动备份仍为复制型，不额外删除缓存差集；导入仅复制源白名单，不删除或移动源；恢复从不删除 Game 的额外项。

## 保留的范围检查与明确失去的保证

- 只操作配置的 Game / 缓存根及业务白名单；保留基本路径规范化、根不重叠、重解析点和白名单范围检查。它们是应用操作范围限制，不是目录身份授权，不是对抗所有路径竞争的安全隔离保证。
- 不改 Windows ACL、用户权限、防病毒设置或系统安全机制。Windows 权限不足、占用/共享冲突、路径和磁盘错误按实际 API 结果报告；不会绕过系统拒绝。
- 不再使用持久还原保护、目录所有权认领、物理身份批准、对局等待、哈希比对跳过、业务文件暂存原子替换、最终内容复验或删除墓碑。旧管理文件和旧历史目录保持原状、忽略、不参与恢复或镜像真值。
- **直接覆盖不是事务**：取消或错误可能保留已完成变更，也可能使正在写的目标部分或截断；已删除缓存项不会自动找回。无单文件/整批回滚、不可变源快照或字节一致性复验承诺。
- 不提供快照、历史恢复点、滚动保留、自愈、坏代回退或历史补齐。成功仅指本次计划范围内 Win32 操作完成，不证明业务语义正确或源目录始终静止。枚举失败不可假装为空，部分失败/取消不得报告成功。
- 配置文件仍严格解析并通过现有配置事务保存；配置损坏/不可读时保留原文件，不用默认值覆盖。配置 CAS 与配置原子保存不代表业务文件仍采用原子复制。
- 退出先发取消，再等待后台返回，不强杀业务 IO；极端内核/驱动阻塞不能承诺固定退出时限。

## 构建（开发者才需要工具链）

使用可信的 LLVM-MinGW C++17 便携工具链（主目标i686/x86，开发亦可x86_64），支持Windows PowerShell 5.1及以上；不修改系统PATH或安装开发环境。推荐指定完整工具目录和独立输出目录。

~~~powershell
.\build.ps1 -ToolchainBin 'X:\portable-toolchain\bin' -BuildDir 'X:\build\lolbackup' -Mode All -Architecture x86
.\run_tests.ps1 -BuildDir 'X:\build\lolbackup' -NoBuild
~~~

发行程序是输出目录中的单个LOLBackup.exe；任何编译、资源、链接、导入检查或测试失败都返回非零。Tests模式可仅重建测试；AuditOnly可对既有程序检查导入。BBS 主程序的导入表应只有 Windows 系统 DLL/API-set 依赖，动态 DLL 加载路径也有独立源级门禁；这一门禁不代表内嵌第三方工具没有 Python/Electron/VC++ 等独立依赖。完整发行还需按组件清单生成/嵌入工具资源并保留许可证。

本次已验证的编译器、CMake、Ninja和JSON输入版本/校验值记录于 [toolchain.lock.json](<toolchain.lock.json>)；自定义工具链不自动等同于本次发行验证，不声称跨任意路径字节级复现。

另有 Bash 入口 [build.sh](<build.sh>) / [run_tests.sh](<run_tests.sh>)；CMake 3.20+在中文/空格路径使用 **Ninja**（传统MinGW Makefiles的ANSI路径后端会明确拒绝并提示改用Ninja或PowerShell）。CMake入口直接将RC编入主target，Unicode/GUI入口只作用于主程序，测试为普通console main。固定工具链、资源与许可证随构建验证记录追踪。**开发者需要编译器，不等于终端用户需要编译器。**
