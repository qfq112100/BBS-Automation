3. 大厅联动与定时全量镜像

阶段行为
首次观测在线 / 大厅启动独立监控默认 500ms；首次在线立即排队物理缓存 → Game，不等第二次确认，不等对局
大厅持续在线按用户间隔（默认 5 分钟，1–1440）将物理 Game 白名单全量镜像到缓存，覆盖并删除受管差集
完整空 Game仅大厅确认在线时，空才作为物理真值清空全部受管缓存项，不动白名单外内容；枚举错误不得假装为空
大厅离线 / 未知停止安排自动任务并请求取消；不追加对局结束/下线备份，不自动清理 Game
再次在线再次恢复当时物理缓存，然后继续定时镜像；失败恢复不会冻结未来定时镜像

在线(1) / 离线(0) / 未知(-1) 只驱动大厅调度。工作线程在文件及复制进度回调只读原子状态；不把对局运行或全会话进程检查作为写许可。

4. 缓存与恢复

自动 fullMirror 在 mirror/verified 删除前边界仅额外做一次新鲜 ProbeLobby，确认仍在线才开始删除，不表示内容复验。离线/未知时即使 Game 随后变空，也不自动复制、删除或补派最终任务。恢复/逐文件/逐块仍无进程探测。取消使用 PROGRESS_STOP 留下当前部分目标，不使用 PROGRESS_CANCEL 删除式清理；错误、覆盖、截断无回滚。

  • 缓存物理白名单是唯一恢复源；不读墓碑解释存活项，不从旧历史补齐。
  • 同内容也覆盖；无 Game 全树预扫、哈希跳过、暂存原子替换或最终内容复验。
  • 空缓存无文件可恢复，不伪造复制成功；不要求“干净保护”批准，也不会阻止后续在线定时镜像。
  • 不提供快照、历史恢复点、滚动代、自愈或坏代回退；旧管理元数据和旧历史目录保留原状、忽略、不参与业务判定。

5. 操作范围与直接模式风险

项目本版本约定
基本范围检查配置绝对路径规范化、Game/缓存不重叠、重解析点与白名单检查保留；不是目录身份批准或强路径竞争隔离
移除的业务保护无持久还原冻结、所有权认领、身份批准、对局等待、哈希跳过、业务暂存原子替换、最终复验、墓碑
Windows 系统边界不改 ACL/系统安全策略，不绕过占用/权限；如实报告 Win32 权限、共享冲突、磁盘和路径错误
直接覆盖风险错误/取消可能留下部分或截断的目标；已经复制/删除的变更不回滚
失败后续行为本次失败明确报告，但还原失败不冻结未来定时镜像；下个周期以当时 Game 为真值
配置保存严格解析、配置 CAS 与配置原子保存保留；损坏/不可读配置不被默认值覆盖，不等于业务文件原子复制
结果诚实排队不是成功；部分失败/取消不报成功；成功不证明内容语义或不可变源快照
退出先请求取消再等后台返回，不强杀 IO；极端内核/驱动阻塞无固定退出保证

12 · 工具中心与完整运行时

TOOLS
  • 第 5 页管理 Rose 1.4.9（直接嵌入 LTK 1.30.4 host/dll/license）与 Akari 1.5.1 完整 Electron 应用。组件按版本释放，不是无运行文件的原生功能移植。
  • 独立 worker，不让准备/检查/启动阻塞 DIRECT 快速恢复；跟随默认关闭，开启后在线启动、离线请求正常关闭、未知忽略，手动启动不要求在线。
  • 已有无效目录只报错，不自动修复。请求关闭可能只缩到工具托盘；强停必须确认，仅限受管工具，不结束游戏或 Riot 客户端。

  • Rose 静态游戏构建兼容阈值 2026-10-28T23:06:41Z 不是电脑时间到期，后续构建需官方 patcher 更新；未做真实游戏注入，不保证账号或服务条款安全。
  • 保留各工具和 Electron/Chromium/Node 等依赖许可；Akari MIT 不能覆盖其他依赖义务。工具 dry-run --verify-tools <绝对隔离根> 不启动真实工具、游戏或同步服务。
